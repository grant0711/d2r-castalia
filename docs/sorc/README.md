## 1. The 1:1 Save-Compatibility Rule

All 30 vanilla Sorceress rows (`*Id 36..65`) are kept with the same row name, `*Id`, `charclass="sor"`, and icon cel so `.d2s` saves, staffmods, and `+skill` items remain 100% compatible.
- **Skill Tabs**: Page 1 = **Fire** (`soskilltree.sprite` frame 2), Page 2 = **Lightning** (frame 1), Page 3 = **Cold** (frame 0).
- **Unlock Tiers**: Rows `1..6` correspond to required character levels **`1 / 8 / 16 / 24 / 32 / 40`**.
- **Prerequisite Arrows**: Declared via `prereqs=[...]` in `registry.SLOTS` and automatically composited onto `soskilltree.sprite` by [`tools/mod_builder/sorc/tree.py`](file:///home/grant/games/d2r/tools/mod_builder/sorc/tree.py).

## 3. Fast CLI Loop (`bin/d2r-sorc`)

```bash
# 1. Inspect the 30-skill map or look up the parallel Fire archetype for a skill:
./bin/d2r-sorc map [fire|lightning|cold]
./bin/d2r-sorc patterns <slug>
./bin/d2r-sorc funcs [query]
./bin/d2r-sorc show <slug>

# 2. Create/edit a variant and activate it:
./bin/d2r-sorc variant <slug> v1 -m "what this variant tests"
./bin/d2r-sorc use <slug> v1

# 3. Run TDD formula lint + neutral/matching/opposing stance simulation:
./bin/d2r-sorc test <slug>

# 4. Build skills + run all 8 verification suites + update docs/site/index.html:
./bin/d2r-sorc build

# 5. Provision or reset a test Sorceress character (while D2R is at character select or closed):
./bin/d2r-char create SORC --class sor --level 55 --wp a3nm
./bin/d2r-sorc char

# 6. Log in-game observations, mark done, compact old variants, and commit:
./bin/d2r-sorc log <slug> "Verified in game: ..."
./bin/d2r-sorc status <slug> done
./bin/d2r-sorc compact <slug>
./bin/d2r-sorc commit -m "sorc(<tree>): <slug> final1"
```

## 4. Core Design Rules

1. **Investment Must Change Feel**: Every active spell must scale a tangible geometry/feel parameter with skill level (missile `Vel` + `VelLev` capped by `MaxVel`, `Range`, AoE radius `calc1`/`cltcalc1`, projectile count `calc2`, or secondary duration) in addition to non-linear damage tiers (`EMinLev1..5`, `EMaxLev1..5`).
2. **Matching-Stance Empowerment & Cross-Stance Fizzle**:
   - Every offensive spell gains a distinct mechanical or geometric empowerment when cast in its matching elemental stance (`skill_handofathena` for Fire, `skill_frenzy` for Cold, `skill_decrepify` for Lightning) and **fizzles immediately** (`Range=1` or `0`, `Radius=0`) when cast in either opposing stance.
   - Every tree's mobility utility skill (`flashfire`, `glacier_step`, `phase_step`) is strictly stance-gated via `restrict="2"` and `State1="sorc_stance_<tree>"`.
3. **Keep Context Small**:
   - Use `d2r-sorc patterns <slug>` and `d2r-sorc funcs` instead of grepping raw TSV tables.
   - Run `d2r-sorc compact <slug>` once a skill is `done` so `specs/<slug>.json` retains only `baseline` and the active variant (`< 10 KB`).
